# 评测详情与候选行

## 定位

评测详情是评测管理域的「读」侧与操作中枢：`/runs` 左栏列表 + 右栏详情，右栏在 `?panel=detail|new|edit&id=…` 三种内容间切换（同一栏位换内容，不弹层、不跳页）。详情页回答「这一轮跑成了什么样」：轮次快照信息行、候选卡片的进度与结果、以及三个右侧主抽屉（执行日志 / 变更详情 / 评分详情）与原文类内容的二级抽屉。**抽屉随主场景走、不脱离使用环境**——一切查看都在右栏就地展开，主抽屉被二级抽屉推开而不是被替换。

## 页面形态与交互

### 列表页

五列：**标题**（首列列名逐字是「标题」，与用例页同形）/ 状态 / 候选数 / 执行模式 / 创建时间。

- 标题列 `fixed: 'left'` 左悬浮 + 数值型表格挂横向滚动（`scroll.x = RUNS_TABLE_MIN_WIDTH`）：最小宽度具名常量求和 **96+80+96+150+240 = 662**，求和式里没有裸数字。
- 宽栏（右栏关）：表格铺满 **1384 / 1384**、无横向滚动；窄栏（视口 800 + 点行打开右栏）：容器 **364 / 662** 可滚 298，标题列 `td`/`th` 恒 **8–248** 不动、状态列 **248 → -50**——左栏窄到装不下五列时标题钉在左边，其余列滑走。
- 表头用 `sticky` 吸顶（禁 `scroll.y`，防常驻空滚动条）；表头与表体横向同步（滚到底 `th.left === td.left`）；五列 `th` 高 29、不折行。

**列表排序**（用户口径：默认「创建时间」倒序，标题 / 状态 / 创建时间三列可排；候选数、执行模式不参与）：

- 默认与服务端同向：`api/runs.ts` 的 `listRunsView` 本就按 `createdAt` 降序，故首屏顺序与「取消排序」后的顺序长得一样（**只看顺序分辨不出这两态，要看表头有没有箭头**）。
- 「标题」列排的是 `EvalRun.caseTitle`——**创建那一轮时的用例标题快照**（run 上没有自己的标题字段）：用例改名不改写历史轮次，所以排的是历史标题；同一用例的多轮标题必然相同，它们的相对位置由稳定排序决定（见下）。
- 「状态」列按**业务生命周期** `idle → running → partial → done`（`RUN_STATUS_RANK`，写成 `Record<EvalRun['status'], number>` 让契约新增状态时 tsc 直接报错）。不按枚举名、也不按中文标签拼音排——那会把「部分完成」插在「未开始」前面。枚举外的状态进不了这张表（`run.json` 不合枚举会被 run-store 的 `safeParse` 跳过，只留 WARN）。
- 文本 / 时间 / 空值 / 稳定排序口径与用例页逐字相同（`compareSortText` / `compareSortTime` 是**就地两份实现**之一，改一处必须同时改另一处）：中文拼音序 + 数字按数值、空值与坏值当最小值、同值行保持服务端 `createdAt` 降序、比较器只写升序语义（方向由 antd 取反）。
- 三态与默认列行为同用例页：默认列「创建时间」进入即降序 → 点 1 次升序 → 点 2 次取消 → 点 3 次回降序；其余列升序 → 降序 → 取消；`defaultSortOrder` 只在**页面初始**生效，点过别的列之后该列的首次方向回到 `sortDirections` 首项（时间列显式写了 `['descend','ascend']`，所以首次点击即降序）。

**守卫缺口**：与用例页同一处的**零自动化守卫**（排序口径不抽模块、不加单测），判据只有本节这几条口径，改这两张表的列时照本节逐条核对。

### 详情页（右栏 detail）

- **顶部信息行**：用例标题 · 代码仓库 · 分支（`repoBranch !== null` 的远端轮次才有这一格）· commit（**全量 40 位**，不截短、不挂 Tooltip）· 工作基目录；`extra` 放「编辑 / 删除」（判据与作废口径见《修改、重跑与删除评测》）。
- **串行进度**：`3/6 已完成`（`completionPercent(done, total)`，`total <= 0` 返回 0，绝不让除零的 NaN 流进界面）。
- **候选卡片列表**，每行一张 Card；卡片底部一行**活动行**只在运行态显示「此刻在做什么」，文案由适配器按同一份词表发下来。
- **排序与名次**：出分后按 总分降序 → 耗时升序（null 当最差）→ tok（输入+输出）升序（`compareRows`）；**名次 = 1 + 严格优于它的行数**，三项全同的行并列同名次，`rank <= 3` 带排名徽标（并列时挂徽标的行可以多于三行）。tok / 轮次两格在**真有子智能体分量**时多一行 Tooltip（缓存命中是派生值、不挂浮层）。
- 串行模式下等待中的卡片显示「串行排队中：前一行结束后自动开始」；diff 被截断时卡片标注「diff 已截断」。
- **按钮矩阵**：执行日志 / 变更详情 / 开始执行或重新执行 / 评分详情 / 重新评分共**五个都常驻渲染**——四个靠 `disabled` 控可用性、执行日志连禁用态都没有（永远可点）；**「终止」是另一个分支**，只有 `preparing` / `running` / `judging` 时存在，其余行态整个按钮不在 DOM 里（`cancelMidTurn: false` 的家 DSH 这一格退化为「关闭运行时」）。
- **吸底操作栏** `Layout.Footer`：**开始**执行所有未完成的行（`isRunnableRow`：`pending` + `failed` + `timed-out` + `canceled` + `interrupted` + `skipped`；**`judged` 不在内**——已出分的行不该被一次误点重跑掉几十分钟），触发 `Modal.confirm` 列出本次将执行的候选清单；**终止**用 `Popconfirm`（杀进程，不可撤销）。全开并发下卡片内另有单行「终止」。

### 候选行表格与行操作（创建 / 编辑表单）

候选行是一张 small `Table`（`run-create-panel.tsx`；字段语义与候选池过滤见《创建评测》）：

- 列序固定 **智能体 ｜ 模型 ｜ 思考强度 ｜（无标题的）操作列**；操作列列名留空、`align` 右对齐；实测列宽 智能体 130 / 模型 330（随内容弹性）/ 思考强度 120 / 操作 80。
- 三个图标 link 按钮 21×21、顺序**上移 / 下移 / 删除**（上移下移 default、删除 danger，`textContent` 为空、悬停 Tooltip 出中文名）；图标按钮与同行下拉中心线一致。
- **删除删的是点的那一行**；删光最后一行是可达状态，空态文案「还没有候选：点下面的「添加候选」加一行」（不出现英文空态）。
- **边界置灰而不是隐藏**：单行时上移与下移都 disabled；两行时第一行上移、第二行下移置灰，换位后置灰跟着行序走。
- **换位换的是提交载荷的行序**（组件守卫直接断言 `onSubmit` 收到的顺序）；换位**不重置任何行**——行 id 与「智能体 / 供应商 / 模型 / 强度」都没变，判它「什么都不作废」、保存前不弹确认框（换位没让任何一行变成另一件事，这是刻意的）。
- **体量**：同一块（两个候选）高 **91px**（thead 29 + tbody 62），行高 30–31px。

### 三个右侧主抽屉：一份几何

「变更详情」「评分详情」「执行日志」三个右侧主抽屉共用**同一份**几何，字面量唯一落点是 `packages/client/ui/src/base/drawer-geometry.ts`：

- `WIDE_DRAWER_SIZE = 'max(50vw, 800px)'`（CSS `max()`，不在 JS 里量窗口）；`WIDE_DRAWER_STYLES` = `wrapper.maxWidth: '100vw'` + `body.padding: 0`。实测：视口 1920 → **960**（50vw 生效）、1432 → **800**（下限生效）、700 → **700**（`maxWidth` 兜底、`x=0`，不撑出屏幕）。
- **高度自适应不写死**：`.ant-drawer-body` 自带 `flex:1; min-height:0; overflow:auto`，内容用 `minHeight: '100%'`（不是 `height`）；**抽屉内唯一滚动容器就是 `.ant-drawer-body`**。
- `body.padding: 0` ⇒ 内边距由每个抽屉的内容自己给：变更详情的汇总条 / 搜索框 / 文件标题条各自带横向 padding（吸顶底色铺满整宽 ⇒ padding 加在标题条自身）、diff 正文不加；执行日志在滚动区 Flex 加；评分详情在最外层加。
- **执行日志抽屉是例外**：虚拟列表自持滚动容器（虚拟化需要确定高度的视口，body 的高度靠 flex 取、给不到那个数）——最外层 `height: '100%'`、固定区占自然高度、列表用 flex 取剩余高度；宽度与 `padding: 0` 两条照旧。
- **环境抽屉有意不统一**：`min(42vw, 640px)`——它是主抽屉内部的第二层抽屉，比主抽屉窄是设计口径。
- 不给抽屉加 `resizable`：宽度口径是确定的，再加可拖拽会让「宽度是多少」出现两个答案。

### 变更详情抽屉

形态是**逐文件**的「文件名 + diff 正文」一个可滚动列表，滚动时当前文件标题吸顶，正文进视口才加载：

- **索引与正文是两种响应**：`?offset=&limit=` → 索引（每页 30、不含任何 diff 正文，按 `offset` / `limit` 分页）；`?file=` → 单文件正文（`file` 优先）。
- **惰性加载**：`IntersectionObserver` 在文件进入视口时触发正文请求，任何一次响应都不携带「全部文件」；没有 IO 时退化为立即渲染；加载中显示 `Skeleton` 而不是空白（空白会被误读成「这个文件没改动」）。**吸顶与惰性是同一个机制**：滚动正是加载的触发器，两件事在同一时刻发生，不需要两套滚动监听。
- **文件标题条**：路径（等宽、`EllipsisText` 省略 + Tooltip 显全量，不用 Tag 包裹）+ `+X −Y`（`white-space: nowrap` 且不收缩）+ 「未跟踪」文字标签——标题条只有这三项，截断 / 二进制标记挂正文那一格；吸顶底色用 `token.colorBgElevated`（否则正文透过来）。滚动容器是 `.ant-drawer-body` 本身，标题 `position: sticky; top: 0`。
- **汇总条**「共 N 个文件 · +X −Y」+ 截断提示，文案沿用「**评分模型看不到它们**」（改成「已截断」会让人以为只是界面没显示全）；搜索框只对**已加载页**做 `includes`，提示语「仅在已加载的 N 个文件里过滤（共 M 个）」，不做服务端搜索。
- `hasBody === false`（被 diff 体积预算丢弃）的条目：标题照常吸顶、正文位置显示「该文件超出体积上限，未包含在本轮评分输入中」且**不给加载入口**——让「被预算丢弃」在界面上是可预期的，而不是点一下才发现没有。
- **正文适配内容高度、不内部滚动**（滚动容器只有 `.ant-drawer-body` 一条）。
- diff 组件用 `react-diff-viewer-continued@4.4.0`（原版 peer 不含 React 19）。**接口错配必须写清**：`oldValue` / `newValue` 收的是**完整文件正文**、不是 diff 文本——把 diff 文本当 `newValue` 会渲染出完全错误的 diff。由 `diff-patch.ts` 的 `reconstructSides` 从 diff 文本还原两侧正文：按 hunk 头行号把两侧各自恢复到真实位置，**缺失行留空洞、不补空串到等长**（补空串会让两侧结尾不同，组件内部的 jsdiff 重新配对尾部，把未修改的行也画成红绿；不补则两侧逐行一致）；同时传 `showDiffOnly={false}` 让空洞如实显示为未修改。`diff` 文本已是服务端算好的唯一真源，另取全文会让「界面显示的改动」与「评分模型看到的改动」变成两次独立计算。
- `file.binary` 为真时显示「二进制文件，没有可显示的文本改动」；两侧都还原成空串时显示「这个文件没有可显示的文本改动」。

### 二级抽屉：原文类内容的「按钮 + 二级抽屉」模式

大段原文（模型原始返回、逐行执行原文）**不占主抽屉正文高度**：入口是按钮，点开在二级抽屉里展示。

- 几何：`NESTED_DRAWER_SIZE = 'min(60vw, 900px)'`（实测 859px = 60vw）；语义槽样式与主抽屉共用一份（`DRAWER_SEMANTIC_STYLES`，只有宽度分档）；`destroyOnHidden` + `mask.closable`。
- **主抽屉被推开 360px**：`MAIN_DRAWER_PUSH = { distance: 360 }`，实测主抽屉 `x` 从 632 → 272。**push 的位移量归属「被推开的那一方」**：rc-drawer 的 `pushDistance = push?.distance ?? parentPushDistance ?? 180`，子抽屉 `open` 时调的是 `parentContext.push()` ⇒ 把 `push` 写在**二级抽屉**上是空转（只挪默认的 180；写主抽屉才是 -360）。`NestedDrawer` 因此**不写** `push`，并由守卫钉住「二级抽屉那一侧不许再写」。
- 三个入口同模式：「原始输出 N 条」（执行日志抽屉固定区，**就地**成行、不折叠，旁有「重新读取」）、「查看原始返回」（评分详情标题右侧按钮，评分详情是「标题 + 右侧按钮」）、卡片底部的「原始结果」（task / ask-user 卡片，同一个件的另一变体）。
- **虚拟滚动只有一个实现**（`base/virtual-list.tsx`：`Listy` + 高度测量 + 退化兜底 + `scrollToKey`），轮次时间轴与逐行原文共用；守卫钉「只许出现在原语里，且两处内容都必须走它」。虚拟化生效：50 行原文只挂载 **9** 个可见节点（宿主 `clientHeight 664` / `scrollHeight 8950`），滚到底降到 2；抽屉正文**没有第二条滚动条**。
- 「下载台账」按钮在原文行上（`ToolbarAction` 的 `placement: 'raw'`，预设里只有它标这一格）；整行渲不渲染由 `rawRowVisible` 判（有原文入口或有要渲的动作才画）。真机原文行 = `原始输出 50 条 · 重新读取 · 下载台账`。
- 原文行三个按钮同形：`className` 逐字相同（`ant-btn-default ant-btn-color-default ant-btn-variant-outlined ant-btn-sm`）、高 24px——三个都是默认边框按钮，没有无边框的 `type="text"`（并排会像另一类东西）。

## 数据与契约

- `RowDiffIndexSchema`：`files[]`（`path` / `insertions` / `deletions` / `untracked` / `hasBody`）+ `total` + `offset` + `insertions` / `deletions`（**全部文件**的增删合计，不是本页）+ `noBodyCount` + `truncated` + `droppedFiles`（被预算丢弃的文件名）。文件顺序 = numstat 两段的输出顺序（不排序）。
- `RowDiffFileSchema`：`path` / `patch`（该文件那一段统一 diff 原文）/ `insertions` / `deletions` / `binary`。**没有 `truncated` 字段**：预算按整文件丢弃、永远不会把一个文件的正文切一半 ⇒「正文显示了一半」这个状态不可能出现，留一个恒为 `false` 的字段会诱导写出永远进不去的分支。
- 路由 `…/rows/[rowId]/diff`：`limit` 服务端封顶 200（`DIFF_PAGE_MAX`）、`offset` / `limit` 非法一律按默认值处理而不是 400（只读展示接口，宽容降级比报错有用）；`file` 参数 `searchParams.get` 已解过码、**不得再 `decodeURIComponent` 一次**（含 `%` 的真实路径会抛 `URIError` ⇒ 500）；路径只用来在内存里比对 diff 段落中的路径字符串，**不参与任何 `path.join`**。
- `getRowDiffFile` 的两条拒绝分开：未知路径 `NOT_FOUND`、`hasBody === false` 的路径 `CONFLICT`（「这个文件不存在于本次改动」与「它存在但正文被裁了」在排障时是两回事）；索引里有、正文段里却没有 ⇒ `INTERNAL`。
- `useRowDiffIndex`（`revalidateOnFocus: false`；`!enabled` 或 id 为空时 SWR key 传 `null`）；`useRowDiffFile` **没有 `enabled` 位**：`path` 为 `undefined` 时 key 传 `null`——这正是「滚动到才加载」的开关，不需要另造布尔；路径要 `encodeURIComponent`。
- **客户端分页**：hook 收 `offset` / `limit`，页面累积已加载页（带「只并当前请求那一页」的守卫，否则晚到的响应会并错页并自我触发下一页）；`DiffView` 的哨兵回调走 ref（内联箭头函数进依赖会让观察者每帧重建、反复触发加载）。
- **30 秒进程内缓存**：键 `(runId, rowId)`、命中即续期、32 条上限按最旧淘汰；语义是「打开抽屉这半分钟内的快照」，与索引 hook 的 `revalidateOnFocus: false` 同口径；不做主动失效（候选中途会写盘，主动失效要在编排层埋钩子）；只在内存、进程重启即失效。
- 预算口径：`truncateDiff(text, settings.diffBudgetBytes)` 默认 **262144 字节 = 256 KB**，按 `diff --git` 整段保留到预算为止，超出部分只留文件名（丢弃的逐个点名写进截断说明）；**单文件正文不做二次截断**。
- `extractDiffFile`（按路径取某文件那段 diff 原文）：**必须复用** `splitDiffFiles` 的切分逻辑（两份切分器漂移的表现是「索引里有的文件，正文永远取不到」）；切出的路径**必须套一次 `rewriteRenamePath`** 再比对（索引路径来自 `--numstat` 且已归一，正文段路径是 `diff --git` 原样的，花括号重命名 `packages/{old => new}/x.ts` 会让两个键不相等；该函数对已归一路径幂等）；同名文件在「已提交」与「未提交」两段都出现时取**未提交**段（倒序扫描）。
- `dark` 由调用方传入 `useAppliedThemeMode()`（即 `themeMode === 'dark'`），**不要**就地再调 `useResolvedTheme()`——它的偏好缺省是 `'dark'`，SSR 兜底那一拍会拿到暗色，diff 按暗色渲染而 `ConfigProvider` 是明亮主题 ⇒ 半亮主题。

## 状态机与时序

- **行态驱动呈现**：活动行只在运行态出现；「终止」按钮仅 `preparing` / `running` / `judging` 时在 DOM 里；出分后卡片按 `compareRows` 重排并挂名次徽标。单行执行 / 重新评分的判据与文案分叉见《修改、重跑与删除评测》。
- **实时刷新**：运行中实时计数走 SSE（token 累计、轮次、耗时）；列表与详情的**快照**另有「有活在跑时每 3 秒」的轮询兜底。
- **抽屉打开时序**：三个主抽屉 `destroyOnHidden`（关了销毁，量几何要等 wrapper 从 DOM 消失再开下一个）；`dark` 在抽屉打开那一刻取值，之后切主题**不追进已挂载的抽屉**、重新打开即正确——「抽屉里是打开时看一眼的快照」的既有口径。
- **惰性加载时序**：首帧只有一条 `?offset=0&limit=30` 索引请求；滚动到哪个文件才出现哪条 `?file=…` 请求；列表底部哨兵元素触发下一页（走 ref 防自我维持循环）。
- **二级抽屉时序**：点原文按钮 → 二级抽屉从右侧推出、主抽屉同时被推开 360px → 原文交给二级抽屉的 body 滚（主抽屉正文不再内套第二条滚动条）。
- **缓存窗口**：改设置（如把 diff 体积上限调回）后，抽屉数据最多 30 秒后生效——TTL 内请求仍返回旧快照属预期。

## 已知边界与取舍

- **transform 会静默杀死 sticky 吸顶**：静止态、无二级抽屉打开时已核实 body 没有任何 `transform` 祖先（`.ant-drawer` 是 `position: fixed`）；但 antd 开关动画在 wrapper 上写过 `transform`（整段移动过程都有包含块），二级抽屉打开期间被推开的主抽屉也被写常驻内联 `transform: translateX(-360px)`——这两处的吸顶是否失效**都没有实测，如实登记**；若再给抽屉加常驻 `transform`，吸顶会静默失效，这一条是护栏。
- **已加载页不回收、列表无虚拟化**：一路滚下去 DOM 会线性涨到「已加载的全部条目」——刻意换来的「不重排」。
- **虚拟化要求宿主高度有界**：量不到高度时 `VirtualList` 退化为全量渲染，症状是**不报错、只是又变慢**（已写进原语文件头；jsdom 靠这条才能数到全部内容）。
- 环境抽屉里那一行 `push` 仍写在二级抽屉上、属空转（机制见上）；效果已由主抽屉那份覆盖。
- **明暗逐态观感未复核**：已量的是几何（与主题无关）；深色下三个图标与置灰态的对比度未实测截图。
- **窄屏（≤700）二级抽屉宽度**只按 `min(60vw, 900px)` 推算，未实测；二级抽屉里超长行有没有横向滚动也未量。
- **两页标题列下限（240）是两份独立常量**：数值相同是「两页标题列同形」的结果，不是共享真源；漂移的代价只是两页最小宽度不同，不是缺陷。
- `scroll.x` + `sticky` 的组合结论只在本机 chromium 量过（rc-table 把 `scrollXStyle` 落 `.ant-table-body`、表头另拆 `.ant-table-sticky-holder`实现细节）；升 rc-table 大版本时要重测这一格。
- 列表页纵向吸顶只各滚了 14 / 16px（两页真机各只有 1 条数据）；「长列表滚很深时表头是否一直吸住」未在真机走到，由 `sticky` 语义与既有用例兜着。
- **真机没有点过「确定」**（保存 PUT，避免动真实数据）：载荷形状（`id` / `effort` 原样回传、全量替换、换位后的行序）由组件守卫直接断言 `onSubmit` 的编辑模式用例与路由测试覆盖。
- 卡片底部的「原始结果」二级抽屉未在真机复现（那一轮没有 task / ask-user 卡片），由「入口文案在不在 + `rawOpen` 透传进抽屉」的用例口径钉住；卡片抽屉的开合走同一份折叠态（键 = 块键 + `|raw`），L0 / L1 一律不持态（分层纪律守卫当场拦 `useState`）。
- 两个列表页的列定义在滚动容器**外面**：守卫抠 `const columns: TableColumnsType<…>` 切片，抠不到直接抛（不抛的话，空切片会让守卫静默通过）。
