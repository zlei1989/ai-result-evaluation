# 功能总览

功能说明域的目录层：三大功能模块与数据模型的清单，每项一句话定位；已落地文章给站内链接，未落地者以《书名号》提名。

详情层文章随内容票逐篇落地、落地后回补本页链接；本页的组织只跟领域逻辑走（增删改查与生命周期视角）。

## 用例管理

固定「同一道题」：仓库 + commit + 考题提示词 + 评分标准项。固定之后，任意候选的产出可被完整复现与追溯。`/cases` 页是列表 + 右侧栏，右栏在「详情 / 创建 / 编辑」三种内容间切换——同一栏位换内容，不弹层。

| 能力 | 一句话定位 |
|---|---|
| 用例存储 | **一用例一文件**：`<casesRoot>/<用例 id>.json`（默认 `~/.aieval-cases`），内容是裸 `TestCase` JSON、**文件名即身份**；坏文件跳过并带原因，列表页出告警条 |
| 创建与编辑 | 标题、考题提示词必填；代码来源与 commit 校验通过才落盘，编辑表单与创建同构、预填 |
| 代码来源 | 本地目录与远端 git 地址共用同一个 `repoPath` 字段、按形态自动判定；远端由服务端自动镜像成裸仓库、跨用例复用，认证走本机 git 的 SSH key 与凭据助手 |
| commit 口径 | 留空 = 默认分支 `HEAD`；填了必须在该仓库中存在（归一成 40 位），候选下拉列最近 20 条、也可手输任意合法 hash |
| 评分标准项 | 组 → 项的权重表（`ID` / `目标` / `权重`），每项只做二元判定、没有部分分；智能生成与智能识别各是一次非流式文本调用，只用设置页的全局默认评分模型 |
| 删除 | 已被评测引用不阻塞删除（确认框不显示引用数、删完的提示才列出）；历史评测靠冗余快照仍可追溯；**删的是用例文件**，随后按「用例变更时自动提交」排一次 git 同步；用例级缓存仓库一并删除，远端镜像不动 |

详情层文章：[用例管理](/features/case-management)。

## 评测管理

让多个候选（智能体 × 模型 × 思考强度）在同一道题、同一起点上各写一遍，再用同一把尺子打分、并排比较。`/runs` 页同样是列表 + 右侧栏。

| 能力 | 一句话定位 |
|---|---|
| 创建评测 | 候选行 = 智能体 + 模型 + 思考强度；执行模式串行 / 并行、默认串行、运行中不可改；创建后落库 `idle`、不自动开跑，「开始」是详情页的显式动作 |
| 候选池过滤 | 模型下拉按智能体接受的协议集合过滤——Claude Code 只吃 `anthropic`、Codex 只吃 `openai`、DSH 两类都吃；不可行组合在创建阶段就消失 |
| 修改与删除 | 修改范围 = 用例 + 执行模式 + 使用智能体评分 + 候选行，只要没有行在运行就能改、被改动的行原地重置；删除先删 `run.json` 再删整目录，镜像不随评测消失 |
| 重跑 | 两个出口：单行执行（只跑当前候选，该行事件清空从头来）与重新评分（只重跑评分那一步，事件追加不清空） |
| 详情与候选行 | 顶部信息行 + 串行进度 + 候选卡片；三个抽屉——执行日志（流式）、变更详情（逐文件吸顶、惰性加载）、评分详情（逐组判定表） |
| 行执行与日志 | 每候选行独立工作区与独立配置目录（串行也独立）；事件日志是执行的唯一真相源，SSE 由它扇出、刷新不丢事件；失败隔离、不限时间 |
| 评分 | 两条通路——纯文本 API 与智能体评分，每一次评分只用一条；尺子是快照进轮次的评分标准项（总分 = 达成项权重之和），评分者 = 设置页全局默认 |

详情层文章：[创建评测](/features/run-creation)、[修改、重跑与删除评测](/features/run-edit-rerun-delete)、[评测详情与候选行](/features/run-detail)、[行执行与日志](/features/row-execution)、[评分](/features/judging)。候选智能体的接入细节见协议规范域：[Codex 接入](/protocols/codex)、[Claude Code 接入](/protocols/claude-code)、[DeepSeek Harness 接入](/protocols/dsh)。

## 设置

`/settings` 页五个 Tab。供应商与评分配置只在设置页配置——用例不持有评分模型，评分与生成一律走全局默认。

| 能力 | 一句话定位 |
|---|---|
| 模型供应商 | 名称 + 协议类型（OpenAI 兼容 / Anthropic 兼容）+ API 地址 + 密钥；协议只决定「模型能否驱动某智能体」，不决定能不能拉清单 |
| 模型清单 | 独立对话框维护：拉取是合并不是覆盖（手工条目不被冲掉），可手工增删、逐条维护上下文窗口与输出上限；窗口未知就不注入，不用兜底数字冒充已知 |
| 评分配置 | 默认评分模型（两种协议都可选）+ 思考强度 + 默认评分智能体 + diff 上限（默认 256 KB = 262 144 字节）；没有「行超时」——执行与评分都不限时间 |
| 工作区 | 工作区根目录默认 `~/.aieval-runs`、**用例目录**默认 `~/.aieval-cases`，两格各自「校验并保存」（必须真写一次再删）；改根目录不迁移已有数据，历史评测显示自己的实际根目录。另带**用例变更时自动提交**开关（`casesRoot` 不是 git 仓库时置灰）与用例同步状态、「提交」/「拉取」两个人工动作 |
| MCP 服务器 | 第 5 个 Tab：name-keyed map（stdio / http 判别联合）、贴入导入、启停、测试连接；候选执行时按行注入三家各自的形状，行级观测格回答「这一行装上没有」 |
| 界面主题 | 跟随系统 / 明亮 / 暗色三档 |

详情层文章：[设置](/features/settings)、[MCP 配置](/features/mcp-config)。

## 数据模型

持久化用磁盘文件（JSON + JSONL 事件日志），不引入数据库——文件人可读、可手工检查。

| 模型 | 一句话定位 |
|---|---|
| `config.json` | `~/.aieval/config.json`（或 `AIEVAL_CONFIG_DIR` 指定目录）**两段一个文件**：应用设置 + 供应商（密钥明文落盘、写盘 `0600`、下行只给掩码）。**用例不在里面**（旧 `cases` 键静默忽略、不迁移）。设置段里的 `mcpServers` 另有**播种**口径：键缺失才播预置两台，删光不复播 |
| 用例文件 | `settings.casesRoot`（默认 `~/.aieval-cases`）下的 `<用例 id>.json`：**一用例一文件**、裸 `TestCase` JSON、文件名即身份、写盘 `0600` 原子替换 |
| 用例同步状态 | `GET /api/cases/sync-status` 的只读快照（是否 git 仓库 / 有无远端 / 待提交数 / 远端领先数…），**只在内存**、不持久化 |
| 工作区目录 | `cases/{caseId}/cache/` 用例级缓存仓库、`remotes/` 远端裸镜像、`{runId}/` 一轮评测的快照与行产物，三类各得其所 |
| 运行快照 `run.json` | `EvalRun` + 候选行 `EvalRow`，每次状态变更整体原子覆盖；七格冗余快照让删掉用例、改掉供应商名字后，历史评测仍说得清当时测的是什么 |
| 评分表快照 | `rubric` 快照进轮次，跑一行读快照、不读用例——改了表，历史分与它自己的满分仍自洽 |
| 契约 | `@aieval/contracts` 的 zod schema：`Provider` / `TestCase` / `Rubric` / `EvalRun` / `EvalRow` / `ScoreResult` / `Settings` / `AgentEvent` |
| 事件日志 `events.jsonl` | 每行一个带单调序号的事件，执行的唯一真相源；`api` 扇出成 SSE，前端按 `seq` 续订、坏行只跳过该行 |

通用口径：时间字段一律 ISO 8601 带时区字符串，实体 id 一律 UUID v4；写盘原子、读盘容忍 UTF-8 BOM。

详情层文章：[数据与存储](/features/storage)。
