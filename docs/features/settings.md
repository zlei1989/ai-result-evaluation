# 设置

## 定位

设置页四个 Tab：**基础**（模型供应商 / 界面主题 / 自定义请求头 / 模型调用重试 / 存储目录）、**评分**、**MCP**、**技能**。当前停在哪个 Tab 记在 URL 里（`?tab=basic|judge|mcp|skills`）：刷新后停在同一 Tab，地址可直接分享；切换用 `replace` 不进浏览器历史（「后退」离开整页，不在 Tab 之间逐个倒退）；未知值与缺省一律回落「基础」，且默认态的地址只有裸 `/settings` 一种写法（`?tab=basic` 不出现）。onChange 自动保存、无保存按钮；配置落盘位置与原子写口径见《数据与存储》。

## 页面形态与交互

- **基础**（一个 Tab 里五张卡，按「开始评测之前先配一次」的先后排：模型供应商 → 界面主题 → 自定义请求头 → 模型调用重试 → 存储目录）：
  - **模型供应商**：每家供应商一行（名称 / 协议类型 / API 地址 / 模型数 / 操作）。协议类型（`openai` / `anthropic`）决定该供应商能被哪些智能体消费——判据是 `acceptsProtocol(metadata, protocolType)` 集合判定（协议是供应商的属性、集合是智能体的能力，两者不混）。`openai` 是 **Responses** 接口（`POST {地址}/v1/responses`），`anthropic` 是 **Messages** 接口（`POST {地址}/v1/messages`）——两条通路（智能体驱动与评分文本调用）用同一个判据；API 地址填到**站点根**即可，缺 `/v1` 由服务端自动补、多写也不会叠。只实现 Chat Completions（`/chat/completions`）的网关不能选 `openai` 协议：请求会落到 `/v1/responses` 上收 404。「模型清单」独立成对话框维护该供应商的模型列表：拉取分两步（先预览上游候选，勾选后才加入清单；勾选已有的会刷新窗口与档位，未勾选的既有条目不被移除），也可手工增删。供应商表格窄卡片时**名称列左悬浮 / 操作列右悬浮**。新增 / 编辑供应商时协议不兼容的智能体项 `disabled`。
  - **界面主题**：`light` / `dark` / `auto` 三档。
  - **自定义请求头**：一张可增删的两列表——**左边键名、右边键值**，一个「添加一行」、一个「保存」、一个「还原」。这几条头会挂到**四家智能体**发往网关的**每一次模型请求**上（不含 MCP / hosted 工具等子请求）。
    - **必须显式保存**（与「界面主题」那种一改就落的开关不同）：一次要填好几行，逐行落盘会让「填了一半的名字」先被保存；「保存」在有未保存改动时才是可点的，「还原」把输入退回已保存那份。
    - **行内校验当场拦**：键名按 HTTP field-name 的 token 语法（不能含空白或冒号）、值里不能有换行（Header 注入）、**同名（忽略大小写）两行同时标红**；只填了值没填键名的行算「填了一半」并拦下保存，**整行全空的新行**按草稿丢弃、不提交。保存交出的是**整张表**（删光 = 一条都不发）。
    - **敏感键的值只见掩码**：键名命中 `key` / `token` / `secret` / `password` / `auth` 的值在出口一律掩码（与 MCP 的 `env` / `headers` 同一把尺）；把掩码串原样存回去 = 未改动，服务端换回落盘原值。
  - **模型调用重试**：一个数字，`0..20`，默认 **10**。语义是「四家智能体的每一次模型请求失败后最多再试几次」（**不含首次调用**），四家用**同一个数**；`0` = 不重试。改完即落盘（与「界面主题」「diff 上限」同一条口径）。
    - **它只数「可重试面」**：重试与否由各厂商自己的分类决定，本仓只给次数。四家共有的可重试面是 5xx / 429 / 超时 / 连接中断；**400 这类确定性错误（请求形状、模型名、工具 schema 不对）不会重试**——重发同一个请求只会再拿一个 400，该改的是配置或网关。网关若把瞬时故障错报成 400，应改网关的状态码（429 / 5xx 才是可重试语义）。
    - **四家各按自己的方言落这一格**：cc 走子进程环境 `CLAUDE_CODE_MAX_RETRIES`、codex 写 `model_providers.aieval.request_max_retries`、dsh 写 overlay 路由的 `retryPolicy.maxRetries`（`mode: normal`）、pi 写会话 `settings.retry`（`0` 落 `enabled: false`）。四家的键本来就都是「重试几次」的语义，故 **1:1 映射、没有 ±1 换算**。
    - **对齐的是次数，不是退避时序**：四家各自按厂商的退避曲线等（dsh 单次封顶 10 s、pi 封顶 60 s、cc 指数退到 36 s 量级、codex 自有），本仓不改。重试不新开 assistant 消息 / 步，界面上的「步数」因此不变。**cc 侧还有一个厂商上限**：`CLAUDE_CODE_MAX_RETRIES` 自 v2.1.186 起封顶 15（只有 `CLAUDE_CODE_RETRY_WATCHDOG=1` 才解除）⇒ 填 16–20 时 cc 实际按 15 跑。
    - **与「整行自动重跑」是两层**：编排层在候选段失败后最多再整行跑 `CANDIDATE_RETRY.maxRetries = 2` 次，它**不读**这一格；两者叠加时最坏是一次候选最多 `3 × (1 + 重试次数)` 次模型请求。⚠️ **400 会走这一层**：本仓把它归成 `AGENT_FAILED`（请求被上游拒绝），而 `AGENT_FAILED` 在「值得整行重跑」的表里 ⇒ 厂商一次都不重发，但整行会再跑最多 2 次。若要改成「确定性 4xx 不整行重跑」，动的是编排层的归因码，不是这一格。
  - **存储目录**（一张「存储目录」卡承担四件东西）：
    - **工作区根目录**：评测落盘的根目录，默认 `~/.aieval-runs`（可改）。
    - **用例目录**：一用例一文件的存放目录，默认 `~/.aieval-cases`。两格各自一个「校验并保存」——名字说的是实话：它确实会写盘（服务端校验通过就落盘），校验失败时**保留用户输入**并把服务端的中文原因显示在结果区。用例目录那一格的说明文案写明「一个用例一个文件，存在 `<用例目录>/<用例 id>.json`」与「**改目录不会迁移已有用例文件**」。
    - **用例变更时自动提交**开关（`casesAutoCommit`，默认**开**）：开 = 用例落盘之后服务端在后台提交并推送；关 = 变更只写文件，要进 git 得点「提交」。**`casesRoot` 不是 git 仓库根时开关置灰**（判据 `syncStatus.isRepo === false`）并跟一句原因——提交这件事压根不可能发生，开着它是骗人。开关直接落盘（`PUT { casesAutoCommit }`），失败**不做乐观翻转**（翻回去会让用户以为是自己点错了）。
    - **同步状态区**（读 `GET /api/cases/sync-status`，**刻意不轮询**）：用例目录不是 git 仓库时是一条 warning「用例目录还不是 git 仓库：用例变更不会提交」+ 原因（含路径与 `git init` 提示）；是仓库时按「正在同步 / 上次同步失败 / 上次同步成功（时间 + 短 hash）/ 有 N 个用例文件待提交 / 另有 N 个无关变更被忽略 / 未配置远端：变更只提交到本地 / 远端是否有新提交未知」逐格出现，**每一格只在它有意义时出现**。状态还没到时画骨架屏；读失败由页面出错误 Alert（组件的 props 里没有 error 位，契约冻结）。
    - **两个人工动作**（`POST /api/cases/sync { action }`，服务跑完一轮才答复，按钮 loading 与服务端 `running` 都体现在这里）：
      - 「提交」的出现条件：`pendingCount > 0 || localAhead > 0`；
      - 「拉取」的出现条件：`remoteAhead !== 0`——`null`（本次没探到：离线 / 没有上游）**也要给按钮**，点了才会看到原因；把「没探到」当成「没有」会让用户以为远端确实没有新提交。`> 0` 时文案带「拉取（远端领先 N 个提交）」；
      - 两个按钮在有阻塞原因（`blockedReason !== null`）或动作正在跑时禁用。
- **评分**：默认评分模型（跨协议候选，按当前评分智能体过滤）、思考强度（`allowClear`，清空 = 未指定；候选域 = 当前模型与当前评分智能体两个档位域的交集，后端 `intersectEfforts` 同一把尺）、默认评分智能体、diff 上限（KB 计，配置存字节，默认 256；同一预算也是「包含步骤」执行过程证据的截断上限）。卡片标题仍叫「评分配置」。
- **MCP**（第 3 个 Tab）：配置面、注入面、失败判据与已知边界自成一篇文章——见[《MCP 配置》](/features/mcp-config)。
- **技能**（第 4 个 Tab，排在 `mcp` 之后——两者都是「往智能体里装外部东西」的配置）：本机启用项的三列表格 + 预览抽屉 + 逐条启停，候选执行时按行装入。目录文法与准入、装入时序、候选级三态判据见[《技能配置》](/features/skills-config)。

## 数据与契约

- 配置文件：`AIEVAL_CONFIG_DIR` > `~/.aieval`（详见《数据与存储》的原子写与 BOM 口径）。落盘是**两段**：`settings` + `providers`，用例不在里面（见《数据与存储》的《用例目录》）。
- **用例两格**（`contracts/src/settings.ts`）：`casesRoot`（默认 `~/.aieval-cases`）与 `casesAutoCommit`（默认 `true`）。下行的两个根目录**恒为绝对路径**——`~` 只在配置文件里作为可读写法，`api/settings.ts` 的 `normalize` 在读取时展开。`casesRoot` 的解析优先级（环境变量 `AIEVAL_CASES_ROOT` 只做默认值）与用例读写共用 `resolveCasesRootForRead`，见《数据与存储》的《路径解析优先级》。
- **`CaseSyncStatus`**（`contracts/src/case-sync.ts`，状态接口与两个动作接口的响应同一形状）：`isRepo`（`casesRoot` 本身是不是 git 仓库根）/ `hasRemote` / `blockedReason`（现在为什么提交不了：非 git 仓库、未配置评分配置；`null` = 可以提交）/ `running` / `lastAttemptAt` / `lastSuccessAt` / `lastCommit`（短 hash）/ `lastError` / `pendingCount`（待提交的**用例**文件数）/ `ignoredCount`（被忽略的无关变更数）/ `remoteAhead` / `localAhead`。**`remoteAhead` 用 `null` 表示「本次没探到」而不是 0**：写成 0，界面就会把一次离线说成「远端没有新提交」。
- **三条路由的分工**：`PUT /api/settings`（整份 `Settings` 同一次原子落盘，两条根目录改动会先做磁盘校验；两格一起改是为了不让设置页出现半生效状态）、`GET /api/cases/sync-status`（只读快照，**永不 500**——不是 git 仓库 / 没配远端都是快照里的一格事实）、`POST /api/cases/sync`（人工动作，跑完一轮才答复；真失败折成 `CONFLICT` + 中文原因）。
- **`customHeaders`**（`contracts/src/settings.ts` 的 `CustomHeadersSchema`，默认 `{}`）：`名字 → 值` 的 map。四家各自翻方言（落点见[《四家横向对比》](/protocols/comparison)的「自定义请求头落点」一行）。值**按字面发送**、不做 `${ENV}` 解析（与 MCP 的占位语义刻意不同：这里用户要发的就是那几个字，敏感值靠出口掩码兜住）；手改 `config.json` 塞进发不出去的一条时，适配器把它摘掉并 WARN（只记键名），本次运行照跑。
- **`modelRetries`**（`contracts/src/settings.ts`，默认 `10`，合法域 `0..20`）：四家智能体每一次模型请求失败后的重试次数（不含首次）。落点见[《四家横向对比》](/protocols/comparison)的「模型请求重试落点」一行；适配器入参是 `AgentRunInput.modelRetries`（可选），**候选执行 / 追问 / 智能体评分 / 用例同步四处各读一次同一份配置快照**。读盘路径（core 的 `normalizeSettings`）把非整数 / 越界的值夹回合法域（`"abc"` ⇒ 10、`999` ⇒ 20、`-1` ⇒ 0），故手改 `config.json` 不会把坏值送进厂商配置面。
- 档位域真机（`GET /api/runs/model-options` 的 `efforts`）：claude `["off","low","medium","high","xhigh","max"]`、codex `["off","minimal","low","medium","high","xhigh","max","ultra","persistent"]`（⚠️ 后两格会被**厂商自己改写**：`ultra` 落到该模型支持的最高档（已知模型上 `xhigh`、未知名模型上 `medium`）、`persistent` 落到 `disabled` —— 名字最「持久」而效果是把推理关掉）、dsh `["off","low","high","max"]`。上游未声明时给「该家完整域 + 关闭档恒含且排第一」。关闭档文案「`off（要求不思考）`」——是「要求」不是断言（codex 选 off 并不会真的停止思考）。
- `judgeEffort` 落盘语义：记「我们要求的」档位，不是「实际生效的」。
- 供应商的 `protocolType` 是单值（协议是供应商的属性）；智能体的 `protocolTypes` 是集合（能力）。

## 状态机与时序

评分配置的消费点：`resolveJudgeRoute()`（评分路由）+ `resolveJudgeEffort()`（档位交集）在评分阶段取**同一份 config 快照**（几次读之间无 `await`）；协议不匹配的拒绝文案是共用的 `protocolMismatchMessage()`（列出该家接受的集合）。

**用例同步的时序**（`api/src/case-sync.ts`）：

1. 用例变更（创建 / 更新 / 删除）落盘之后，`api/cases.ts` 的 `scheduleSync` 读一次 `casesAutoCommit`：关掉就**什么都不做**（变更只在磁盘上，状态区会显示「有 N 个用例文件待提交」）；开着则 `enqueueCaseSync` 排队，**绝不 await**——保存的响应必须立刻返回。
2. 自动触发有 **1 秒防抖**（连续保存合并成一轮）；人工动作**立即跑**（点一次就该立刻有反应）。队列是**串行**的：同一时刻只有一轮在跑，跑动期间的变更合并成一轮收尾同步；人工动作压过自动触发的排程（拉取比「顺手提交一次」更严）。
3. 一轮的动作顺序：不是 git 仓库 → 直接回来（不是失败）；未配置评分配置 → 抛中文 `CONFLICT`（整块同步不跑）；逐文件提交（拉取时要求工作区里没有未提交的用例文件）；提交完才 `fetch`（没有本地提交要推、也没有远端要合时不联网）；落后就先快进、分叉才请智能体裁定合并；有本地领先才 push（退避重试 3 次）。
4. 人工动作的 Promise 在**最后一轮**跑完后 settle，答复的是最新状态快照——「提交完了」与「还剩 N 个没提交」是两句话，不能都报成功。
5. 状态接口要回答「远端有没有新提交」，唯一诚实的答案是 `git fetch` 之后再看；探测有 15 秒上限、结果缓存 30 秒（这个窗口内的重复读复用上一次结果）。

## 已知边界与取舍

| 边界 | 处置 |
|---|---|
| `loadConfig` 不做 zod 校验、不 strip 未知字段 | 手改 `config.json` 写坏 kind 时由调用方判 `AGENT_KINDS` 枚举兜住（`getProvider` 抛裸 Error 无 HTTP 语义） |
| 三个评分生成动作（智能生成 / 识别 / 调整）只用设置页全局默认、不带模型 id 入参 | 未配置默认评分模型 ⇒ 三个按钮禁用 + Tooltip |
| effort 档位强度的效力未证实（同档抖动不小于档间差） | 界面只展示「我们要求的档位」，不给「高档=更准」暗示 |
| `casesRoot` 不是 git 仓库根、或未配置「评分配置」 | 自动同步**整块不跑**：开关置灰 / 状态里写明中文原因。**不悄悄用回退文案把文件提交掉**——那会让用户以为同步链路是通的 |
| 同步状态只活在内存、不做启动补偿 | 重启后「上次同步 / 上次提交」归零不影响正确性（git 事实在磁盘上）；漏掉的同步靠本页「提交」按钮手动补 |
| `remoteAhead === null`（没探到）时仍显示「拉取」 | 把「没探到」写成 0，界面就会把一次离线说成「远端没有新提交」；点了会看到具体原因 |
| 关掉自动提交后用例变更只在磁盘 | 状态区「有 N 个用例文件待提交」是唯一提示，两态都必须让用户看得见 |
| 自定义请求头只作用于**发往网关的模型请求** | MCP / hosted 工具等厂商自己发的子请求不保证带上；dsh 还会按名字滤掉自己的**保留头**（同名只会被静默丢掉） |
| `modelRetries` 与编排层的整行自动重跑是**两层** | `CANDIDATE_RETRY.maxRetries = 2` 不读这一格；两层叠加时最坏 `3 × (1 + 重试次数)` 次模型请求。改这一格不改变「失败后整行重跑几次」 |
| 400 等确定性 4xx **不在厂商重试面** | 本仓只给次数、不改厂商的可重试清单：普通 400（请求形状 / 模型名 / 工具 schema）一次都不会被厂商重发。本仓把它归成 `AGENT_FAILED`，编排层仍会整行重跑最多 2 次——那是本仓的一层，不是厂商的请求级重试；要消掉它得新增一个「确定性 4xx」归因码并从 `TRANSIENT_CANDIDATE_RETRY_CODES` 里排除 |
| 重试次数对齐、退避时序不对齐 | 四家的等待是各自厂商的（dsh 单次封顶 10 s、pi 60 s、cc 指数退到 36 s 量级、codex 自有）；同一次失败在四家墙钟不同，界面只保证「最多再试几次」这一个数一致 |
| 调到 20（上限）时可能先撞上看门狗 | 看门狗仍是空闲 180 s / 单轮模型往返 600 s；默认 10 的退避链通常在 600 s 内收场，更高时会先被按 `timed-out` 收掉（这是「不让一次挂死无限拖」的取舍，不是缺陷） |
| 改 `casesRoot` / `workspaceRoot` 不迁移已有数据 | 旧产物留在原目录，历史记录显示自己的实际路径；界面上两格的说明文案都写明了这一点 |
