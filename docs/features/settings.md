# 设置

## 定位

设置页承载平台级的全部配置：模型供应商、评分配置、工作区（含**用例目录**与**用例变更自动提交**）、界面主题。onChange 自动保存、无保存按钮；配置落盘位置与原子写口径见《数据与存储》。

## 页面形态与交互

- **模型供应商**：每家供应商一行（名称 / 协议类型 / API 地址 / 模型数 / 操作）。协议类型（`openai` / `anthropic`）决定该供应商能被哪些智能体消费——判据是 `acceptsProtocol(metadata, protocolType)` 集合判定（协议是供应商的属性、集合是智能体的能力，两者不混）。「模型清单」独立成对话框查看与刷新该供应商的模型列表。供应商表格窄卡片时**名称列左悬浮 / 操作列右悬浮**。新增 / 编辑供应商时协议不兼容的智能体项 `disabled`。
- **评分配置**：默认评分模型（跨协议候选，按当前评分智能体过滤）、思考强度（`allowClear`，清空 = 未指定；候选域 = 当前模型与当前评分智能体两个档位域的交集，后端 `intersectEfforts` 同一把尺）、默认评分智能体、输出契约（只读两段文案——提示词契约与 schema 契约的投影）、diff 上限（KB 计，配置存字节，默认 256）。
- **工作区**（一张「工作区」卡承担四件东西）：
  - **工作区根目录**：评测落盘的根目录，默认 `~/.aieval-runs`（可改）。
  - **用例目录**：一用例一文件的存放目录，默认 `~/.aieval-cases`。两格各自一个「校验并保存」——名字说的是实话：它确实会写盘（服务端校验通过就落盘），校验失败时**保留用户输入**并把服务端的中文原因显示在结果区。用例目录那一格的说明文案写明「一个用例一个文件，存在 `<用例目录>/<用例 id>.json`」与「**改目录不会迁移已有用例文件**：旧文件留在原目录，用例列表只认新目录」。
  - **用例变更时自动提交**开关（`casesAutoCommit`，默认**开**）：开 = 用例落盘之后服务端在后台提交并推送；关 = 变更只写文件，要进 git 得点「提交」。**`casesRoot` 不是 git 仓库根时开关置灰**（判据 `syncStatus.isRepo === false`）并跟一句原因——提交这件事压根不可能发生，开着它是骗人。开关直接落盘（`PUT { casesAutoCommit }`），失败**不做乐观翻转**（翻回去会让用户以为是自己点错了）。
  - **同步状态区**（读 `GET /api/cases/sync-status`，**刻意不轮询**）：用例目录不是 git 仓库时是一条 warning「用例目录还不是 git 仓库：用例变更不会提交」+ 原因（含路径与 `git init` 提示）；是仓库时按「正在同步 / 上次同步失败 / 上次同步成功（时间 + 短 hash）/ 有 N 个用例文件待提交 / 另有 N 个无关变更被忽略 / 未配置远端：变更只提交到本地 / 远端是否有新提交未知」逐格出现，**每一格只在它有意义时出现**。状态还没到时画骨架屏；读失败由页面出错误 Alert（组件的 props 里没有 error 位，契约冻结）。
  - **两个人工动作**（`POST /api/cases/sync { action }`，服务跑完一轮才答复，按钮 loading 与服务端 `running` 都体现在这里）：
    - 「提交」的出现条件：`pendingCount > 0 || localAhead > 0`；
    - 「拉取」的出现条件：`remoteAhead !== 0`——`null`（本次没探到：离线 / 没有上游）**也要给按钮**，点了才会看到原因；把「没探到」当成「没有」会让用户以为远端确实没有新提交。`> 0` 时文案带「拉取（远端领先 N 个提交）」；
    - 两个按钮在有阻塞原因（`blockedReason !== null`）或动作正在跑时禁用。
- **界面主题**：`light` / `dark` / `auto` 三档。

## 数据与契约

- 配置文件：`AIEVAL_CONFIG_DIR` > `~/.aieval`（详见《数据与存储》的原子写与 BOM 口径）。落盘是**两段**：`settings` + `providers`，用例不在里面（见《数据与存储》的《用例目录》）。
- **用例两格**（`contracts/src/settings.ts`）：`casesRoot`（默认 `~/.aieval-cases`）与 `casesAutoCommit`（默认 `true`）。下行的两个根目录**恒为绝对路径**——`~` 只在配置文件里作为可读写法，`api/settings.ts` 的 `normalize` 在读取时展开。`casesRoot` 的解析优先级（环境变量 `AIEVAL_CASES_ROOT` 只做默认值）与用例读写共用 `resolveCasesRootForRead`，见《数据与存储》的《路径解析优先级》。
- **`CaseSyncStatus`**（`contracts/src/case-sync.ts`，状态接口与两个动作接口的响应同一形状）：`isRepo`（`casesRoot` 本身是不是 git 仓库根）/ `hasRemote` / `blockedReason`（现在为什么提交不了：非 git 仓库、未配置评分配置；`null` = 可以提交）/ `running` / `lastAttemptAt` / `lastSuccessAt` / `lastCommit`（短 hash）/ `lastError` / `pendingCount`（待提交的**用例**文件数）/ `ignoredCount`（被忽略的无关变更数）/ `remoteAhead` / `localAhead`。**`remoteAhead` 用 `null` 表示「本次没探到」而不是 0**：写成 0，界面就会把一次离线说成「远端没有新提交」。
- **三条路由的分工**：`PUT /api/settings`（整份 `Settings` 同一次原子落盘，两条根目录改动会先做磁盘校验；两格一起改是为了不让设置页出现半生效状态）、`GET /api/cases/sync-status`（只读快照，**永不 500**——不是 git 仓库 / 没配远端都是快照里的一格事实）、`POST /api/cases/sync`（人工动作，跑完一轮才答复；真失败折成 `CONFLICT` + 中文原因）。
- 档位域真机（`GET /api/runs/model-options` 的 `efforts`）：claude `["off","low","medium","high","xhigh","max"]`、codex `["off","minimal","low","medium","high","xhigh","max","ultra","persistent"]`、dsh `["off","low","high","max"]`。上游未声明时给「该家完整域 + 关闭档恒含且排第一」。关闭档文案「`off（要求不思考）`」——是「要求」不是断言（codex 选 off 并不会真的停止思考）。
- `judgeEffort` 落盘语义：记「我们要求的」档位，不是「实际生效的」。
- 供应商的 `protocolType` 是单值（协议是供应商的属性）；智能体的 `protocolTypes` 是集合（能力）。

## 状态机与时序

评分配置的消费点：`resolveJudgeRoute()`（评分路由）+ `resolveJudgeEffort()`（档位交集）在评分阶段取**同一份 config 快照**（几次读之间无 `await`）；协议不匹配的拒绝文案是共用的 `protocolMismatchMessage()`（列出该家接受的集合）。

**用例同步的时序**（`api/src/case-sync.ts`）：

1. 用例变更（创建 / 更新 / 删除）落盘之后，`api/cases.ts` 的 `scheduleSync` 读一次 `casesAutoCommit`：关掉就**什么都不做**（变更只在磁盘上，状态区会显示「有 N 个用例文件待提交」）；开着则 `enqueueCaseSync` 排队，**绝不 await**——保存的响应必须立刻返回。
2. 自动触发有 **1 秒防抖**（连续保存合并成一轮）；人工动作**立即跑**（点一次就该立刻有反应）。队列是**串行**的：同一时刻只有一轮在跑，跑动期间的变更合并成一轮收尾同步；人工动作压过自动触发的排程（拉取比「顺手提交一次」更严）。
3. 一轮的动作顺序：不是 git 仓库 → 直接回来（不是失败）；未配置评分配置 → 抛中文 `CONFLICT`（整块同步不跑）；逐文件提交（拉取时要求工作区里没有未提交的用例文件）；提交完才 `fetch`（没有本地提交要推、也没有远端要合时不联网）；落后就先快进、分叉才请智能体裁定合并；有本地领先才 push（退避重试 3 次）。
4. 人工动作的 Promise 在**最后一轮**跑完后 settle，答复的是最新状态快照——「提交完了」与「还剩 N 个没提交」是两句话，不能都报成功。
5. 状态接口要回答「远端有没有新提交」，唯一诚实的答案是 `git fetch` 之后再看；探测有 15 秒上限、结果缓存 30 秒（这个窗口内的重复读复用上一次结果）。

## 已知边界与取舍

| 边界 | 处置 |
|---|---|
| `loadConfig` 不做 zod 校验、不 strip 未知字段 | 手改 `config.json` 写坏 kind 时由调用方判 `AGENT_KINDS` 枚举兜住（`getProvider` 抛裸 Error 无 HTTP 语义） |
| 三个评分生成动作（智能生成 / 识别 / 调整）只用设置页全局默认、不带模型 id 入参 | 未配置默认评分模型 ⇒ 三个按钮禁用 + Tooltip |
| effort 档位强度的效力未证实（同档抖动不小于档间差） | 界面只展示「我们要求的档位」，不给「高档=更准」暗示 |
| `casesRoot` 不是 git 仓库根、或未配置「评分配置」 | 自动同步**整块不跑**：开关置灰 / 状态里写明中文原因。**不悄悄用回退文案把文件提交掉**——那会让用户以为同步链路是通的 |
| 同步状态只活在内存、不做启动补偿 | 重启后「上次同步 / 上次提交」归零不影响正确性（git 事实在磁盘上）；漏掉的同步靠本页「提交」按钮手动补 |
| `remoteAhead === null`（没探到）时仍显示「拉取」 | 把「没探到」写成 0，界面就会把一次离线说成「远端没有新提交」；点了会看到具体原因 |
| 关掉自动提交后用例变更只在磁盘 | 状态区「有 N 个用例文件待提交」是唯一提示，两态都必须让用户看得见 |
| 改 `casesRoot` / `workspaceRoot` 不迁移已有数据 | 旧产物留在原目录，历史记录显示自己的实际路径；界面上两格的说明文案都写明了这一点 |
