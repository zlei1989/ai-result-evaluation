# 终结过程档案形态：知识文章为唯一真源

> **状态**：已落地（2026-10-09，提交 c375d31）。

`docs/superpowers/` 下的 specs / plans / notes 曾是本项目的过程真源（设计决策、实施计划、冒烟与探测记录），累积到 58 份 / 约 3.2 万行，且被约 20 处源码注释与 AGENTS.md 直接引用。我们决定（58 份档案，原文笔误 57）：以 VitePress 知识库的知识文章层取代它们——文章按主题域组织、自含全部现时结论（抽象纳入、可倒推原文内容）、正文不反链任何过程档案；知识库建成后过程档案**整体退役删除**，此后**不再新增**过程档案，关账时把设计决策与冒烟证据直接回写进对应知识文章（见 GLOSSARY「关账回写」），过程可追溯性交给 git 历史。

**为什么**：三重动因——(1) 过程档案按时间戳而非领域组织，人读像考古、AI 读无法导航；(2) 知识文章若反链档案，档案就永远删不掉，「提炼」就成了永远的半成品；(3) 档案与文章并存必然出现两个真相源，对 AI 的危害大于没有知识库（AI 会信过期结论）。

## Considered Options

- **保留档案为证据层，文章反链原文**：可对勘、保留证据链，但单一真源永不成立，且 3.2 万行原料的维护负担永续。被否。
- **档案形态照旧 + 周期性熔炼清理**：工作流零改动，但「后续删掉」成为永远兑现不了的承诺。被否。

## Consequences

- 删除档案时须同步修复约 20 处源码注释直链、AGENTS.md 引用与 eslint 报错文案中的档案路径（P2 单独成票），并用断链守卫验证全仓引用计数归零。
- 证据链的形态改变：git 历史成为唯一的过程可追溯层，知识文章不再携带「哪次冒烟、哪次探测」的文件指针，只在正文陈述结论。
- 「不迁就历史文档」成为组稿规则：文章结构只跟领域逻辑（如增删改查）走，历史文档仅作提炼取材。
