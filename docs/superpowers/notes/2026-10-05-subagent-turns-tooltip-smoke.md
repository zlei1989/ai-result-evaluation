### 3.3 实测到「没采到」那条诚实路径（claude 行）
该行 `subagentTurns` 是**显式 null**，并且 events 里有一条点名 WARN，逐字：

```text
[WARN] 读不到子智能体 bey1yc1n7 的会话文件，这一行的 tok / 缓存命中 / 轮次**不含**它们（不编造）
```

盘上核对：该行 `.agenthome` 里**确实找不到**那个子智能体的会话文件（递归列举无命中）⇒ 这不是适配器找了错路径，而是收尾那一刻文件不在盘上（CLI 未落或落在别处）。

## 5. 补记（同日）：用户报的 claude 缺陷与修复后的复验

**用户所报**：claude 的卡片里 tok 与轮次两个浮层**都没有子智能体那一行**。

**根因（`497f9e7` 修，盘上三处互证）**：旧判据是「事件流里每个 `subagentId` 都必须有同名转录文件」。
而事件流里的 `bey1yc1n7` **不是**真子智能体的另一个 id 形状——它是 **CLI 给非 Agent 任务（一条带 `description` 的 Bash）发的 `task_*` 条目**，
它**永远没有转录**（它的 `parentToolUseId` 就是**真子智能体自己那条 Bash** 的 id，`input.description` 逐字就是我们显示成「名字」的那句）。
真派发的 wire id 与文件名 `agentId` **同值**（文件名 / 转录内 `agentId` / 主会话 `toolUseResult.agentId` 三处相等）。
⇒ 幻影让整格作废（`missing` 非空 ⇒ 全量或 null）⇒ 两格 null ⇒ 两个浮层都只剩主会话。
**决定性证据**：旧代码的 WARN 会列出**所有**读不到的 id，而盘上那条 WARN **只点了 `bey1yc1n7`**——说明真子智能体的文件当时**读得到**。

**修法**：聚合读者改为**按会话目录枚举** `projects/<项目>/<会话 id>/subagents/agent-*.jsonl`（该目录 per-session ⇒ 不会串到别的 attempt），
保留三条诚实规则：任一文件读不出 ⇒ 整格 null + 点名**文件 id**；**事件流报过而一个转录都没有 ⇒ null + 点名 wire id**（绝不 `{0,0,0}`）；流没报且目录空 ⇒ `{0,0,0}`。
`sessionId` 采不到时**不再猜目录**（枚举下猜错会把别的会话的转录算进这一行）；抽屉里的单子智能体读取语义不变（幻影得 null 是对的）。

**修复后复验（只重跑 claude 那一行，同一轮 `11a5feb5…`）**：

| | 修复前 | 修复后 |
|---|---|---|
| `turns` / `subagentTurns` | 3 / **null** | **7 / 2** |
| `subagentTokens` | **null** | **14720 / 13568 / 1457** |
| 悬停 `tok` | 只有主会话一行 | `主会话 输入 16,357 · 缓存 62,592 · 输出 2,009` + **`子智能体 输入 14,720 · 缓存 13,568 · 输出 1,457`** |
| 悬停 `轮次` | **没有浮层** | **`主会话 5 轮` + `子智能体 2 轮`** |

算术自洽：`16357 + 2009 + 14720 + 1457 = 34,543`（卡片上就是 `tok 34,543`）；`5 + 2 = 7`（卡片上就是 `轮次 7`）；`2 ≤ 7` 成立。

**同时登记（另一面，未修）**：幻影 `task_*` 条目在**派发面板**里会多出一条「子任务」（它没有转录、名字是那句 Bash 描述）——见 spec §4 R19；
本次修复的规则③（「事件流报过 ⇒ null」）用的核对神谕正是那个**分不出幻影**的谓词，已在 spec §2.3 / §3 / R19 与代码 JSDoc 四处登记：
「只有幻影、无真派发」时会给出 null + 一句把 Bash 叫成子智能体的 WARN（方向保守；盘上暂无该实例，触发条件未刻画）。
