## 4. 未覆盖项与后续计划

1. **未真实跑一轮候选**（不使用真实 CLI 与额度）：④ 的「已评分行」、⑥ 的「运行中」、⑦ 的「用例已删除」三项都用**磁盘播种的快照**构造。播种只新增了 `D:\export\runs\<seed-uuid>\run.json`，收尾时已删除；它验证的是**界面判定与服务端语义**，不验证「真 agent 跑出来的行」——那部分由既有的评测冒烟记录覆盖。
2. **计划与实现的一处偏离（我判定实现是对的，是计划写错了）**：计划 Task 10 的第 7 条预期「原用例已删除时，只改执行模式**保存成功**且 caseId 不变」。实现按 spec §5.1 口径 4 的校验链（第一步「用例存在」）返回 **404 `NOT_FOUND 用例不存在`**，磁盘不写。这与「开始 / 重新评测」对同类轮次的处置一致（用例已删 ⇒ 只能看不能跑），且占位项已提示「请重新选择」⇒ 采纳实现，计划该条作废。
3. **服务端 409（运行中）在界面上不可达**：⑥ 里两个入口已置灰，因此走不到「点下去拿 409」那条路；该分支由 `route-runs.test.ts` 的 409 用例与 api 层用例覆盖。
4. **编辑表单可被无提示导航离开**（点另一行会跳详情，未保存内容静默丢弃）；**手输 `?panel=edit&id=…` 可绕过面板的 `hasLiveRows` 置灰**（靠服务端 409 兜底）。两者都是本页 URL-as-truth 设计的后果，非本次引入，留作后续设计讨论。
5. **全仓 `pnpm test` 的满载争用（已用判别实验定性）**：见 §5。
