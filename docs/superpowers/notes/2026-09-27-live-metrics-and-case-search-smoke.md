## ⑤ 全量测试暴露并修掉的一个缺陷（本批自己引入的）

第一次全量 `pnpm test` 报出 **573 条未捕获异常**（vitest 明确警告「可能造成假阳/假阴」），
栈顶是 `patchRow ← Timeout._onTimeout orchestrator.ts`：**耗时心跳在定时器回调里抛异常**。
触发条件是真实存在的（快照被清理 / 工作区根目录被改走 / 磁盘满），而定时器里抛出的异常
没有任何调用方能接住——生产上可能打崩进程。

修法：心跳写入失败时**自停**并记 DEBUG（真正的故障会在收尾那一次写入上以 ERROR 现身），
守卫 `orchestrator-live.test.ts` 的「心跳写入失败（快照已不存在）时自停，不把异常抛到定时器外」
（先见过它红：`ServiceError: 评测不存在` 直接从 `advanceTimersByTime` 抛出来）。
修完后同意用例文件从 12 失败 + 573 未捕获异常 → 4 失败（**全部是 `Test timed out in 60000ms`**）+ 0 未捕获异常。
