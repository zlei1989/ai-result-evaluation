### C3. **v3 里根本没有对应物的概念（v2 独有）**——重写时不能只改号

实测 v3 全文**零命中**：

| 概念 | v3 命中 | 说明 |
|---|---|---|
| `AskUserAnswer` | **0** | 答案回填（`selected` 装选项标签、`custom` 随 `multiSelect` 变、未知标签照样显示）在 v3 里**没有契约** |
| `recommended` / `allowOther` / `multiSelect` / `secret` | **0** | `ask-user` 卡片的选项语义在 v3 里**没有契约** |
| 「七态」/ `autoResolution` | **0** | `AskUserOutcome` 的七态（含 `auto-resolved`）在 v3 里**没有契约**；v3 §7.2 只提 `outcome: 'unavailable'` |
| `TaskStep` | **0** | 步骤形状在 v3 只以内联形式出现在 §5.1：「`steps[]`（`{id, subject, status, owner?, blockedBy?}`）」 |
| `commitModel` / `TaskListArgs` | **0** | 设计文档的「不进 UI」处置**仍然正确**，但理由不能再引 v2 的节号 |

⇒ **重写动作**：这些概念的**定义必须就地内联**（它们本身是对的、也是必需的），
并注明「来源为 v2 系设计稿；v3 未收编，本设计自行定义」。
**不能**改成「见 v3 §x」——那会指向一个不存在的东西。

## D. v3 自身的一处不一致（影响本设计的 `LogNodeStatus`）

| 位置 | 内容 |
|---|---|
| v3 **§2.6** 的 `SubagentRecord` 类型 | `status: 'running' \| 'completed' \| 'failed' \| 'stopped' \| 'unknown'`（**5 值**） |
| v3 **§5.5** 的渲染要求（逐字） | 「**状态取值固定为六种**：`running` / `completed` / `failed` / `stopped` / `unknown` / **`未收场`**」 |

⇒ v3 的**类型与自己的渲染要求对不上**：类型 5 值，要求 6 值（多「未收场」）。

**对本设计的含义**：D33 给 `LogNodeStatus` 加了 `unsettled`（未收场）——
这是**按 v3 §5.5 的要求**做的，方向正确；但它**超出了 v3 §2.6 的类型定义**。
重写时须写明这一点，否则下一个读者会以为是本设计自己发明的。

## E. antd 6 的 API 修正（重写 §9.6 选型表 / §5.1 / §6.8 时必须一并改）

见 `2026-10-02-exec-log-visual-measurements.md` §5 的完整表。摘要：

| spec 现写 | 改为 | 依据 |
|---|---|---|
| `List`（§9.6 四处） | **`Listy`** | 控制台实测废弃警告，antd 6.6+ 明示 |
| `Drawer width={…}`（§5.1 / §6.8） | **`size={…}`** | 同上；`size` 收 `number \| string`，可直接给 `max(50vw, 800px)` |
| `maskClosable` | `mask={{ enabled: true, closable: true }}` | 同上 |
| `Divider orientation="left"` | `titlePlacement="start"` | 同上 |
| `Segmented multiple`（§9.6 备选） | 用 `Tag.CheckableTag`（§9.6 已写此备选） | antd 6 的 `Segmented` 不支持多选 |

**已确认 spec 无需改的**（我一度误判，读全上下文后更正）：
`Collapse items[].extra`、`Collapse destroyOnHidden`、`Breadcrumb items` —— 都**是** antd 6 的现行 API；
带 `@deprecated` 的是它们的**旧**写法（`children` / `destroyInactivePanel` / `menu`）。

## F. 依赖可能可以减一条（`@rc-component/virtual-list`）

- spec §7.2 要求显式登记 `@rc-component/virtual-list`（并改 AGENT.md 的依赖表）。
- 实测：antd 6 的 **`Listy`**（`antd/listy`）依赖 `@rc-component/virtual-list@^1.4.0`，
  即**把它封在里面**，并额外提供：`virtual?: boolean`、`itemHeight?`、`height?`、
  `rowKey`（寻址用）、`ref.scrollTo({ key, align })`、`sticky?`、`group?`、`onScroll?`。
- ⇒ **若改用 `Listy`，§7.2 可以不再新增直接依赖**，`ui` 包的依赖面不扩大。
  好处：少一个「必须显式登记、否则 antd 改依赖会静默断掉」的风险点（spec §13 已列为风险）。
- **需在重写时确认**：`Listy` 是否逐项测量动态高度（spec §7.2 选 virtual-list 的头号理由就是这条）。
  它依赖了 virtual-list，但**有没有透传动态测量**要看实现，不能假定。

## G. 重写时的结构建议（待与「冗余审查」的报告合并）

基于 B/C 的实测，方向已经清楚：

1. **契约与界面规则不再分离陈述**：§4.1 被引 68 次是结构病。
   每个界面小节（§5.x/§6.x）就地写出它用到的那几格契约，而不是 `§4.1` 指回去。
   §4 保留为**完整类型定义**（供实现照抄），但界面小节不再依赖读者跳转。
2. **修订叙事全部搬进附录**：§8.1–§8.5（197 行）是追溯用的，不该挡在正文里。
   正文只留「现行口径」，历史留在附录，且**同一条口径只写一次**。
3. **引用一律不用裸节号**：改成「概念名 + 所在小节」或直接内联。
   C2 那类「同号不同义」的引用是重写时必须清零的。
4. **补两节新内容**：
   - **视觉与尺寸**（数据来自 `2026-10-02-exec-log-visual-measurements.md`）：
     token 表、组件实测尺寸、结构几何、对比度实测与取舍、内嵌陷阱。
   - **规范对齐说明**：v2 独有概念的就地定义（C3）+ v3 自身不一致的处置（D）。
