# 冒烟测试方法论

## 定位

冒烟测试是本仓的真机验证缝：启动真实服务、按真实用户路径逐项操作，并用 CLI 复核落盘事实，页面与磁盘互证。它补的是单测与 jsdom 覆盖不到的那一层——本仓 FAQ 维护规矩点名「测试环境 ≠ 运行环境」：打包器改写、解析器差异、子进程环境差异都会造成「单测绿、真机红」，这类问题只能在真机上撞见，发现即按 FAQ 格式归档。

具体形态：起 web-next（`http://localhost:3083`），用 MCP 浏览器工具按**真实用户路径**逐项操作（输入、按钮、弹窗、导航、拖拽），并用 CLI 复核落盘事实（配置文件、git 分支与 diff）。规则简明真源是 `AGENTS.md`「冒烟测试」节；MCP 浏览器工具的 `filename` 路径规则与几何断言细则在 [Playwright MCP](/guard/playwright-mcp)（活文档，互链不复制）。本篇展开三件事：四要素记录契约、页面与磁盘互证口径、真机红/绿判据。

每次冒烟后，四要素写进对应计划/关账记录的「冒烟」小节，不新建过程档案；关账时按回写纪律把结论熔炼进知识文章（ADR 0001），过程可追溯性交给 git 历史。

## 形态与交互

- **起真服务**：`pnpm dev` 起 web-next（`http://localhost:3083`）；端口被占用先 kill 占用进程再启动。dev server 必须能写工作区根之外——评测落盘全在工作区根外（默认 `~/.aieval-runs`），在受限沙箱里起的 dev 所有写盘一律 `EPERM`、接口全 500，症状与功能缺陷一模一样（排障先想沙箱/权限，再想代码）。
- **页面侧操作**：MCP 浏览器工具走真实用户路径——输入、按钮、弹窗、导航、拖拽。截图只作留档，不作判据；几何断言口径见「状态机与时序」。
- **CLI 侧复核**：`curl` 打接口、读配置文件、`git` 看分支与 diff——页面展示的每个关键事实都到磁盘上复核一遍。
- **记录落点**：四要素写进本次改动的计划/关账记录的「冒烟」小节。

## 数据与契约

四要素是冒烟记录的固定契约，缺一不可：

| 要素 | 实际形状 |
|---|---|
| 范围清单 | 逐项判定 ✅ / ❌ / ⚠️ / 跳过+理由，附关键实测值；跳过必须给理由与替代证据（先例：「本次会话没有浏览器自动化工具，客户端行为由 runs.test.tsx / run-events.test.tsx 共 38 条 jsdom 用例钉住」；「周期长且与被测链路无关」） |
| 操作路径 | 可复跑的命令序列（bash 块）或逐项操作描述 |
| 证据 | 浏览器 + CLI 互证：报错与日志原文逐字照抄（HTTP 状态码、dev 日志行、SSE 帧原文），关键实测值记到字段级（如 `disabled: false`、`weightStillOldBeforeApply: "7"`） |
| 未覆盖项与后续计划 | 读不出来的写「未覆盖 + 原因」；**只记实测值，不写「看起来正常」** |

- **判定值**：✅（实测通过）/ ❌（实测失败）/ ⚠️（部分成立，收口时可带 `→已修` 与修复 commit）/ 跳过+理由（基线口径，AGENTS.md）。
- **页面与磁盘互证**：一次页面动作必须在两条通道同时留痕，单侧成立不算成立。
  - 不落盘方向：页面两轮操作都没点「保存」，`GET /api/cases` 复读——用例评分项 `html-doc` 的权重仍是 7 ⇒「全程不落盘」由页面操作与磁盘复读共同钉住。
  - 双通道方向：一次 `PUT` 原样快照后，SSE 流立刻收到 `event: run-updated` 帧，dev 日志同步出现 `[INFO] [runs] 评测已修改`——同一动作在两条通道都留痕。

**真机红/绿判据**：

- **绿** = 关键实测值与预期逐字相等，且互证成立（两条通道读出同一事实）。
- **红** = 行为差异可定位、证据可 grep：dev 日志原文（如 `POST …/generate-judge-prompt 400 in 4ms`）、错误 body 逐字命中、探针读到的异常值。
- **假红不算红**：带负载机器上的 `Test timed out` 是噪声不是回归——先看 `tests` 累积项，比上次大 2 倍以上就别把红当回归；红必须红在断言/报错原文。
- **假绿也算问题**：环境差异导致的假绿（单测绿、真机红）按 FAQ 规矩先修掉，再追加厂商 FAQ 条目并同步《故障索引》目录层。

## 状态机与时序

一轮冒烟的固定时序：

```text
起服务：pnpm dev（web-next :3083；端口被占先 kill 占用进程；写权限须覆盖工作区根外）
  └─ 按范围清单逐项操作（真实用户路径：输入 / 按钮 / 弹窗 / 导航 / 拖拽）
       ├─ 页面侧：几何断言读 getBoundingClientRect()；截图只留档不判据
       ├─ CLI 侧：curl / git / 配置文件读回，复核落盘事实
       └─ 每项落判定（✅ / ❌ / ⚠️ / 跳过+理由）与关键实测值
  └─ 撞见运行期问题：先修掉 → 按 FAQ 四格追加厂商 FAQ → 同步《故障索引》
  └─ 收口：四要素写入本次计划/关账记录的「冒烟」小节
  └─ 关账回写：结论熔炼进对应知识文章（ADR 0001）
```

- **几何断言别靠眼睛**：判断「宽度变了」「布局塌了」一律读 `getBoundingClientRect()`（`read_picked_element` 或 `browser_evaluate`），不要凭截图判断——2px 的差异在截图里看不出来，但会决定用例红不红。工具细节与 `filename` 路径规则见 [Playwright MCP](/guard/playwright-mcp)。
- **截图闭环**：`filename` 传完整绝对路径，存完立刻用逐字相同的路径读回；读不回就当作图片不存在，不得拿它支撑任何结论。
- **新增守卫仍要走变异验证**：真机绿只证明这一轮没踩到，守卫的区分力要靠制造缺陷见过红，见[变异验证](/guard/mutation-verification)。

## 已知边界与取舍

| 边界 | 状态 | 处置与判据 |
|---|---|---|
| 凭截图/肉眼判断几何 | 禁止 | 2px 差异截图看不出但决定红绿；判据一律 `getBoundingClientRect()` |
| 无浏览器自动化工具的会话 | 跳过+理由 | 给替代证据（jsdom 用例数与文件名点名）——不是「没测」，是「换尺子测」 |
| 拖拽在 jsdom 不可达 | 冒烟补位 | 容器尺寸 0，真实拖拽只在真机可达（如 Splitter 松手不弹回这类行为）；拖拽类操作优先排进范围清单 |
| 受限沙箱起 dev server | 环境坏 | 写盘全 `EPERM`、接口全 500；替用户重启 dev 一律用完整权限（评测落盘全在工作区根外） |
| 误落到别处的截图产物 | 不删 | 列出来交给用户；删文件前先读 [PowerShell](/guard/powershell)「文件删除安全」 |
| 真实模型调用花额度 | 预算约束 | 批几轮跑几轮；「全程不落盘」类验证靠不点保存 + 复读接口，不靠多跑一轮 |
| 冒烟不代替门禁 | 分工 | 冒烟验真机行为，全量测试留给门禁；带负载时的红先隔离复跑再定性 |
